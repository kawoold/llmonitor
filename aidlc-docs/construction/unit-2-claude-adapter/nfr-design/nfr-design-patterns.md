# NFR Design Patterns — Unit 2: Claude Provider Adapter

## Pattern 1: Exponential Backoff with Uniform Jitter (Retry)

**Applies to**: `Provider::chat_completion()` wrapping `ClaudeAdapter::send()`

**Design**:
```
attempt 1 → on retryable error: sleep 500ms × jitter → attempt 2
attempt 2 → on retryable error: sleep 1000ms × jitter → attempt 3
attempt 3 → on retryable error: return Err (no more retries)

jitter_factor = 0.9 + (OsRng.next_u32() as f64 / u32::MAX as f64) * 0.2
              → uniform in [0.9, 1.1)
```

**Retryable conditions**: `ProviderError::ServerError(_)` and `ProviderError::RateLimited`

**Non-retryable conditions**: `AuthFailed`, `ClientError(_)`, `Timeout`

**Rationale**: Jitter prevents thundering-herd on Anthropic rate limits. Timeout is excluded because retrying a timed-out request risks duplicate execution on the upstream side.

## Pattern 2: Shared HTTP Client (Singleton per Adapter)

**Applies to**: `ClaudeAdapter` struct

**Design**: `reqwest::Client` is constructed once in `ClaudeAdapter::new()` and stored as a struct field. All calls to `send()` reuse the same client instance.

```rust
pub struct ClaudeAdapter {
    api_key: ApiKey,
    client: reqwest::Client,  // constructed once, reused
}
```

**Rationale**: `reqwest::Client` maintains an internal TCP connection pool. Re-creating it per request abandons pooling, increasing latency and file descriptor usage.

## Pattern 3: Newtype Redaction (API Key Secrecy)

**Applies to**: `ApiKey(String)` — inherited from Unit 1

**Design**: `ApiKey` implements `Debug` and `Display` to emit `"[REDACTED]"` rather than the actual key value. The raw `&str` value is only accessible via an explicit method (`as_str()` or similar), never via standard trait formatting.

**Rationale**: Prevents accidental key exposure in log lines generated by `tracing::instrument` spans, `{:?}` debug prints, or error message formatting.

## Pattern 4: Pure Translation Functions (Testability)

**Applies to**: `translate_request()` and `translate_response()`

**Design**: Both functions take their input by reference/value and return their output with no I/O, no async, no global state access.

```rust
// Pure — unit-testable without mocking
pub fn translate_request(req: &OpenAiChatRequest) -> Result<AnthropicRequest, ProviderError>;
pub fn translate_response(resp: AnthropicResponse) -> (OpenAiChatResponse, RawUsage);
```

**Rationale**: Separation of translation logic from HTTP I/O allows exhaustive unit tests of all BR-U2-* rules without network mocking or async test harnesses.

## Pattern 5: Fail-Fast Input Validation (Cache Control Extension)

**Applies to**: Parsing of `anthropic_cache_control` from `OpenAiChatRequest.extra`

**Design**: If `anthropic_cache_control` is present in the request's extra fields but fails `serde_json::from_value::<AnthropicCacheControlHint>()`, the translation immediately returns `ProviderError::ClientError("malformed anthropic_cache_control: ...")`. This propagates to the proxy handler as HTTP 400 before any Anthropic API call is made.

**Rationale**: Silent ignore of malformed extension fields hides client bugs. Failing fast gives clients actionable feedback. Out-of-range message indices (valid JSON, valid type, but index beyond message array length) are still silently ignored per BR-U2-04.

---

## Pattern 6: Structured Minimal Logging

**Applies to**: `ClaudeAdapter::send()` and `Provider::chat_completion()`

**Design**:
```
INFO  [claude_adapter] model="{model}" status={http_status} input_tokens={n} output_tokens={n}
WARN  [claude_adapter] retry attempt={n} delay_ms={n} error="{e}"
ERROR [claude_adapter] all retries exhausted error="{e}"
```

No request bodies, no response content, no API key fragments are included in any log line.

**Rationale**: Prompt content is sensitive; token counts and status codes provide operational visibility without privacy risk.
